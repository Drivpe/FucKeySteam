### 2.4 四份 Dr7 实现的位运算原文

| 文件 | 位运算（逐字） | 槽 | 语义 | 长度 |
| --- | --- | --- | --- | --- |
| `hwbp16.py` | `dr7 &= ~0xFFFFFFFF` → 循环 `dr7 \|= (1 << (2 * i))` | 0–3 多槽 | 执行 | 1 B |
| `hwbp16b.py` | `ctx.Dr7 = (ctx.Dr7 & ~0xFFFFFFFF) \| 0x1` | 仅槽 0 | 执行 | 1 B |
| `hwbp_ctrl.py` | `dr7 = ctx.Dr7 & ~0xFFFFFFFF` → `dr7 \|= 0x1` | 仅槽 0 | 执行 | 1 B |
| `hwbp_data.py` | `dr7 \|= 0x1` → `dr7 \|= (0x1 << 16)` → `dr7 \|= (0x3 << 18)`，终值 `0x000D0001` | 仅槽 0 | **写** | 4 B |

**语义分组（实测修正：原"3 套语义"框架错误，已推翻）**：

前一轮把 4 个"都碰 `Dr7` 字段"的文件当成一个家族，据此得出"4 份实现 3 套语义"。**这个框架已被代码相似度实测推翻**——"共同碰一个寄存器字段"是**邻接**，不是**同源**。

Jaccard 相似度（非空非注释逻辑行，归一化空白）实测：

| 对 | J | 判定 |
| --- | --- | --- |
| `hwbp_ctrl.py ↔ hwbp_data.py` | **0.869** | 唯一真正的复制体对 |
| `hwbp16b.py ↔ hwbp_ctrl/data` | 约 0.4–0.5 区间 | 同族邻近变体 |
| `hwbp16.py ↔ hwbp16b/ctrl/data` | **0.27–0.28** | **异族，技术路线不同** |

**正确的分组**：
- **族 A（guard-page 页保护路线）** = `{hwbp_ctrl.py, hwbp_data.py}` 核心 + `hwbp16b.py` 邻近变体。这三份**同源**，差异落在目标 RVA 集合、监控的属性名字符串、是否有读内存辅助函数（211 行共同 / 17 行差异；179/66）。
- **族 B（硬件执行断点路线）** = `{hwbp16.py}` **独立**。它用 Dr0–Dr3 硬件断点、零侵入，与族 A 的页保护路线**语义上不可互换**，Jaccard 0.27–0.28 证明其非同源。

**对 §8.1「逐位等价」的直接影响**：等价断言天然只对**族 A 内部**成立（`hwbp_ctrl ↔ hwbp_data` 的 Dr7 位模式逐位相等，已确证）。`hwbp16.py` 是多槽实现，是**另一条路线的代码**，它的 `Dr7` 编码恰巧相似属于巧合，不是复制关系的证据。

### 2.4.1 异族的硬判据（比 Jaccard 更直接）

四条独立证据，全部指向 `hwbp16.py` 与族 A **在 interface 层就已分裂**：

| 判据 | `hwbp16.py` | 族 A（`hwbp16b`/`ctrl`/`data`） |
| --- | --- | --- |
| 函数签名 | `def set_hwbp(hThread, addrs)` —— **复数** | `def set_hwbp(hThread, addr)` —— **单数** |
| 导入 | `import sys, os, ctypes, time, traceback` | 同（四份一致，均为平铺 import，**无一份** `import probe_lib`） |
| 页保护断点 | **不涉及** | 由 `probe_lib.py` 承载（`PAGE_GUARD` 全目录仅 `probe_lib.py` 命中） |
| 实现手段 | 直接 `GetThreadContext`/`SetThreadContext` 裸操作 Dr0–Dr3 + Dr7 | 同手段，但语义是单槽 |

**最强判据是函数签名**：`addrs`（列表）vs `addr`（单值）。两个函数**调用约定不兼容**——同一处调用点无法同时喂给两者。这不是"同一 interface 的不同参数取值"，是**两个不同的 interface**。

**由此推翻 §4 原结论**："把 4 份收成 1 个函数"这个任务陈述本身**建立在一个错误前提上**。正确表述是：族 A 内部 3 份可收成 1 个函数；`hwbp16.py` 是另一件事。

复现：`grep -n 'def set_hwbp' *.py` / `grep -rn 'PAGE_GUARD' *.py`

**已排除的伪实现（此结论不变）**：`dbg_child.py:78` 与 `probe_lib.py:47` 只有 `("Dr7", ctypes.c_uint64)` 的 CONTEXT 结构体字段声明，**无写入**，是宿主层不是编码实现。
复现：`grep -n 'Dr7' *.py`

### 2.5 四份共有的结构性缺陷（子代理发现，本轮已复核）

**缺陷 A：无条件抹掉全部 4 槽。**
四份都写 `& ~0xFFFFFFFF`，一次清空槽 0–3 的启用位与 RW/LEN。
`hwbp16.py` 靠 `for i in range(4)` 循环重填缓解；其余三份**只重填槽 0**，槽 1–3 的既有配置静默丢失。
复现：见 2.4 表内字面。

**缺陷 B：GD 位（bit13）与 GE/LE（bit8–9）从未处理。**
`hwbp_data.py` 是四份中**唯一真正设数据断点**的，而数据断点场景下 GD=0 会使 DR7 写入不生效。这条对它最要紧。
复现：`grep -n '0x2000\|<< 13' hwbp_data.py`（预期无命中）

**缺陷 A 的化石证据（已复核，勿误判为可删）**：`hwbp16.py` 的 `set_hwbp` 循环体：

```python
for i in range(4):
    dr[i] = 0
    if i < len(addrs):
        dr[i] = addrs[i]
        dr7 |= (1 << (2 * i))
```

`dr[i] = 0` **不是冗余**。当 `len(addrs) < 4` 时，尾部槽走不进 `if` 分支，`dr[i] = 0` 正是**清掉旧地址**的那一步——删掉它，`Dr1`/`Dr2`/`Dr3` 会残留上一次调用写入的地址，而此时对应槽的 L 位已被 `dr7 &= ~0xFFFFFFFF` 清掉。

只有 `i < len(addrs)` 的那几次迭代里的清零是多余的。
**对 §8.1「逐位等价」的直接影响**：新函数必须复现这个语义，否则在 `len(addrs) < 4` 时等价断言会失败。这不是"复制体演化的残留"，判断为残余逻辑是错的。

复现：`sed -n '52,70p' hwbp16.py`

## 4. 纯函数边界（#2 的真实设计约束）

> **本节已按 §2.4 的修正重写。** 原框架把 4 个碰 `Dr7` 的文件当一个家族，据此设计的 interface 会**同时容纳两条不相干的技术路线**，是错误的抽象。

### 4.1 真实边界：两条路线，不是四个成员

| 路线 | 成员 | Dr7 用途 | 是否同源 |
| --- | --- | --- | --- |
| **A · guard-page 页保护** | `hwbp_ctrl.py` ↔ `hwbp_data.py`（J=0.869 真复制体）、`hwbp16b.py`（J≈0.65 邻近变体） | 页保护命中后读 `Dr7`，编码**单槽执行**或**单槽写** | 是（族内可合并） |
| **B · 硬件执行断点** | `hwbp16.py`（J=0.27，**异族**） | 直接用 Dr0–Dr3 多槽硬件执行断点，零侵入 | 否（独立实现） |

**关键判断**：`hwbp16.py` 出现在"Dr7 实现清单"里，是因为它**也写这个字段**，不是因为它是路线 A 的复制体。它俩的 `Dr7` 位运算**恰好都是执行断点语义**，属于**技术上的必要相似**（x86 只有这一种编码方式），不是复制关系的证据。

**由此得出的抽象决策（必须由 spec 裁定）**：

- **方案 α（推荐）**：`make_hw_bp` 只覆盖**路线 A**（单槽 + `clear_all_slots` 语义）。`hwbp16.py` 的多槽能力**不进这个 interface**，它的多槽需求另开一张票，属于路线 B 的独立重构。
  - 理由：一个 interface 服务两条不相干路线，就是把两条路线的耦合固化进新代码。深度来自"小 interface 承载多行为"，不是"大 interface 承载所有历史"。
- **方案 β**：`make_hw_bp` 用一个 `addrs` 列表参数同时容纳两条路线（路线 A 传长度 1，路线 B 传长度 1–4）。
  - 代价：把"两条路线"伪装成"一个参数的不同取值"，维护者看不出这是两个系统。**但它是 §8.1 逐位等价最容易达成的路径**，因为 `hwbp16.py` 的循环逻辑天然被 `addrs` 长度表达。

**§8.3 的行为表因此需要重读**：表中 `hwbp16.py` 那一行**不是路线 A 的变体**，而是**跨路线的兼容需求**。若采方案 α，该行从"必须表达"降为"另票处理"。

### 4.2 路线 A 内部的 interface（不受上述分歧影响）

覆盖 `hwbp_ctrl.py` / `hwbp_data.py` / `hwbp16b.py` 三份所需：

```python
make_hw_bp(prev_dr7, addrs, *, rw, length, clear_all_slots=True) -> (dr7, (dr0, dr1, dr2, dr3))
```

逐份核验：
- `hwbp_ctrl.py` → `addrs` 长度 1，`rw=0`（执行），`length=0`（1B），终值 `0x1`
- `hwbp_data.py` → `addrs` 长度 1，`rw=1`（写），`length=3`（4B），终值 `0x000D0001`
- `hwbp16b.py` → 同 `hwbp_ctrl.py`（Dr7 输出逐位相等，已确证）

**`clear_all_slots=True` 是缺陷 A 的显式化**（§2.5）。默认 `True` = 逐位等价现存全部行为（§8.1）；改 `False` 即开启修正路径（留给缺陷票）。

## 5. 建议先做 #2 的理由（供 spec 的 rationale 段）

- **纯整数运算**。目标函数的**实现**只做位运算：不 import ctypes、不碰 Windows API、不碰样本 → Linux 侧可验证。（现存 4 份脚本本身都 import ctypes，这正是要抽出来的原因。）
- **族 A 三份**（`hwbp_ctrl` / `hwbp_data` / `hwbp16b`）已有逐字位运算原文（§2.4），其中 `hwbp_ctrl ↔ hwbp_data` 是 J=0.869 的高置信复制体对，等价性是**可机械判定**的，不是主观判断
- 完成后可立即用 §2.4 表的真实字面量建断言：对每份现存实现，新函数的输出必须与它逐位相等（含 §2.5 的两个缺陷，依 §8.1）
- 它验证的是**"收成深模块"这条路本身**走不走得通——走通了再动那 38 份主循环（`grep -l 'WaitForDebugEvent' *.py | wc -l` = 40）

**注意**：这不是"先做小的"这种泛泛排序，而是**它能否被验证**决定了后面所有建议的可信度。38 份主循环没有等价性判据，`hwbp` 有。这是唯一的排序依据。

**目标函数名以 §8.2 为准**（`make_hw_bp`，非子代理原提的 `make_dr7`）。

## 6. 仓库纪律（拆工单时子代理必须继承的契约）

**本仓库最强的约束**。`FucKeySteam/docs/agents/domain.md` 的漂移登记表实测 **40 行**记录，全部是同类认知错误，且有数条写明"same error shape ... now hit for the third time"。

**对本次重构的直接含义**：子代理在这个目录上工作，最容易犯的错与逆向侧**是同一类**——把"没搜到"当成"不存在"。§2.1 的每个数字都已带复现命令，正是为了防这个。

**spec 与工单必须显式继承以下五条**：

1. **禁止裸行号引用**。`host.c` 曾在一个改动里让八处行号同时失效。改为提供**复现命令**（`grep -n ...`），或在同一改动内重新核验行号。
2. **邻接 ≠ 归属**。Nuitka 常量池里的相邻不构成模块边界。该错误已被记录三次（`src.utils.resources`、round-5 §2.4/§3、`#7` 候选 A）。
3. **缺失 ≠ 不存在**。"没看到窗口"与"窗口不存在"是两件事；`catch {}` 曾把异常渲染成"窗口数=0"。负观测必须列出**所有活解释**才能用来支持论断。
4. **纠正票据的方式**：先**追加评论**，再把正文改到一致，**不得静默改写历史**。
5. **术语**：用 `CONTEXT.md` 与 `KeySteam-弹窗-完整行为规格.md` 的词。最高频混淆对：验证码弹窗 / 倒卖可耻（篡改警告）；闸门 / 完整性自检；本地 trailer / 远程清单。

**注意**：`CONTEXT.md` 是**样本领域**术语表（票据/弹窗/完整性），**不是脚本架构的**。架构词汇用 `codebase-design` 技能那套（module / interface / depth / seam / adapter / leverage / locality），不要漂移成"组件""服务""API"。

## 8. 操作者已裁定（本轮）

### 8.1 等价优先，缺陷另开票 —— **已定**

**决策**：新函数的行为必须**逐位等价**于**族 A 的三份实现**（`hwbp_ctrl` / `hwbp_data` / `hwbp16b`），**包括保留** §2.5 的缺陷 A（`clear_all_slots` 语义）。缺陷**另开一张票**处理。

> 操作者原话针对"4 份实现"，按 §2.4 修正为族 A 的 3 份。`hwbp16.py` 不在等价断言范围内——它是异族（§2.4.1），是否另行重构由 §4.1 的方案裁定。

**决策理由（操作者）**：先拿到可机械判定的安全网（"新函数输出 = 旧实现输出"逐位相等），缺陷的影响面单独查。

**由此派生的必开票 —— 优先级高于重构本身**：

> 查证 `hwbp_data.py` 的数据断点**是否曾经真正生效过**。

`hwbp_data.py` 是全目录**唯一**设数据断点的实现，而它从未处理 GD 位（bit13）。若 GD=0 导致 DR7 写入不生效，则该脚本的历史日志是在**断点未生效**的前提下产生的。这不是代码整洁问题，是**可能影响既有实验结论的正确性问题**。

需查清并写入结论：（a）GD 位在当前这些运行的 CPU/OS 上是否真的必要（需证据，不能照搬手册）；（b）若必要，`hwbp_data.py` 的历史日志中"命中数"从何而来；（c）该结论是否波及 `docs/suppressing-the-dialog*.md` 或票据 `#16`–`#18` 的任何既有判断。

**同时**：§2.4 的 3 条（族 A）逐字位运算原文即为该票的断言基线——新函数对每份实现的输出必须逐位相等。

### 8.2 interface 定型 —— **已定**

**决策**：**一个**函数，一次返回全部 5 个数（Dr7 + Dr0–Dr3）。

```python
make_hw_bp(prev_dr7, addrs, *, rw, length, ...) -> (dr7, (dr0, dr1, dr2, dr3))
```

**决策理由（操作者 / 建议采纳）**：§2.5 缺陷 A 的成因正是"只填了一半"。返回单一对象使"只调一个、忘调另一个"在物理上不可能，直接堵死该 bug 的成因类别。

**对 §4 的修正**：§4 中子代理建议的"另配 `make_dr_slots`"方案**已被否决**。单一函数同时覆盖 Dr7 编码与地址槽分配。

### 8.3 `hwbp16.py` 归属 —— **已定（§4.1 方案 α）**

**决策**：`make_hw_bp` **只服务族 A 三份**（`hwbp16b` / `hwbp_ctrl` / `hwbp_data`）。`hwbp16.py` **不进**该函数，**另开一张票**单独审。

**派生**：`hwbp16.py` 的票需自行界定其范围（是否重构、是否与族 A 统一 interface、是否保持零侵入）。**它不是本次 #2 的一部分。**
