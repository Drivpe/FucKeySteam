# 06 — 统一 `read_pystr()`：3 个脚本改用库函数（**含行为变更**）

**What to build:**

3 个脚本（`hwbp16b`、`hwbp_ctrl`、`hwbp_data`）里的 `read_pystr()` 定义删掉，改为从 `probe_lib` 取用，并**统一为「有偏移回退 + 有可打印过滤」那一版**。

> ## ⚠ 这是本次重构中唯一有行为变更的票
>
> 其余各票都是「搬位置，行为不变」。本票**有意改变行为**，必须单独验收、单独记录。

## 变更内容与理由

现存两版的行为不同，差异已被独立执行证实：

- **谨慎版**：固定偏移读失败时回退尝试其他偏移，并过滤不可打印字符
- **直接版**：只读固定偏移，不过滤

同一段含脏字节的内存（`b"set\x01Modal"`）：谨慎版得到 `b'cleanName'`，直接版得到 `b'set\x01ModacleanName'`——**把相邻结构的字节串接进了返回值**。

统一为谨慎版，因为直接版的行为是**缺陷而非设计**。这是本次偏离「逐位等价优先」原则的唯一一处，判据是「被取舍的两版中存在明确更正确的一版」。见 `docs/adr/0002` 的修订节。

## 必须记录的后果

`hwbp_ctrl.py` 与 `hwbp_data.py` 迁移后，**日志中的字符串命中统计会变化**——这是统一 `read_pystr` 的**预期效果**，不是迁移引入的 bug。

**必须在迁移记录中写明这一点**，避免后人看到日志差异时误判为迁移出错。建议在脚本内的注释或迁移记录里注明「本次起字符串解析改用带过滤的版本，命中数可能减少」。

## 验收方式

本票**不能**用常规的「日志逐行对拍」验收——因为行为有意改变。

**运行环境**：跑样本需 Windows + 提权，机制见 `../ELEVATION-HOWTO.md`。执行器带提权闸，非提权时会拒绝——**不要绕过**。

改为：

1. 先用函数级对拍证明库函数与「谨慎版」旧实现逐位等价（覆盖全部偏移回退分支与过滤边界）
2. 再运行 3 个脚本，确认日志中**除字符串解析相关的行之外**其余全部一致
3. 对字符串解析相关的行，差异必须可解释为「脏数据不再被串接」

- [ ] 3 个脚本的 `read_pystr()` 定义已删除，改为从 `probe_lib` 取用
- [ ] 库函数与「谨慎版」旧实现在函数级对拍中逐位相等（含全部偏移回退分支）
- [ ] 3 个脚本的日志差异仅出现在字符串解析相关的行
- [ ] 每处差异可解释为「脏数据不再被串接」，无无法解释的差异
- [ ] 差异已写入迁移记录，注明「命中数变化是预期效果」
- [ ] 本票与第 05 票分开提交，两者的变更不混在同一处

**Blocked by:** 02（库中需先有参数化的 `read_pystr()`）

**与第 05 票的关系（非阻塞，但须知）：** 两票碰**完全相同的 3 个文件**（`hwbp16b`、`hwbp_ctrl`、`hwbp_data`），只是文件内不同的函数——05 改 `set_hwbp`，本票改 `read_pystr`。它们**不互相阻塞**，可以并行。

但两者若各自独立提交，会在同一文件上产生冲突。两种执行方式都可行：

- **合并执行**：一次编辑同时完成两个函数的迁移，但**提交信息必须分开说明**，且验收时两层分别对照（05 逐位相同、本票差异可解释）
- **先后执行**：先做 05（无行为变更，先建立干净的基线），再做本票。本票的日志对照以此为基线

**推荐先后执行**——本票是唯一有行为变更的一票，干净的对照基线能显著降低验收难度。
