# 11 — `hwbp_ctrl.py` 的 `logged` 被两处共用，导致目标输出永远为空

**What to build:**

修掉 `hwbp_ctrl.py` 的一个**功能性缺陷**：该脚本**从未产出过任何一条属性名记录**，因为日志配额被调试噪音耗尽。

## 缺陷

`logged` 计数器被**两处共用**，而其中一处是高频噪音：

```
第 154–155 行（DW HIT 行 —— 每个命中都打，是调试噪音）：
    if logged < MAX_LOG:
        logged += 1
        L("*** DW HIT @%.3fs rip=%#x ...")

第 173–174 行（属性名记录行 —— 本脚本存在的唯一理由）：
    if logged < MAX_LOG:
        logged += 1
        L("[%s] @%.3fs caller=%s (rva=%s) ...")

第 200 行（汇总）：
    L("匹配目标属性名的命中: %d (已记录 %d 条)" % (sum(callerHist.values()), logged))
```

`MAX_LOG = 400`，而 `DW HIT` 行**先执行**、命中量 40 万级。**前 400 次命中就把配额耗尽**，此后第 173 行的 `logged < MAX_LOG` **永远为假**。

**结果**：属性名记录行**从未写出过一条**。

## 实证

9 份正常 `hwbpCtrl_*.txt` 日志（`fixverify` / `ws04base` / `ws04post` / `ws05base` / `ws05post` / `ws06final` / `ws06post` / `ws06pre` 等）实测：

```
DW HIT 行:     400 条
属性名记录行:    0 条        ← 目标输出，从未产出
日志总行数:      412
```

复现：`for f in hwbpCtrl_*.txt; do echo "$f: $(grep -c 'caller=' $f)"; done`

**汇总段的 `已记录 400 条` 是假的**——那 400 条全是 `DW HIT` 噪音，不是属性名记录。这个措辞会误导读者以为目标输出有 400 条。

## 影响

**这是本目录里"最该产出结果却没产出"的一处。** `hwbp_ctrl.py` 的设计目的（其文档字符串自述）是：

> 不再猜「哪个地址是构造点」，而是从运行期反查「谁调用了 getattr+call，且属性名是 setModal / setWindowTitle / ...」

而这条链**从未跑通**——不是因为机制问题，是因为**日志配额写错了变量**。

工单 06 在做 `read_pystr` 对拍时发现了这个现象（它如实报告「日志层面没有出现任何字符串解析差异」，根因是属性名记录行为 0 条），但它把它当作「差异不可见」的原因，**未进一步追到配额被耗尽这一层**。本票补上。

## 与 `#16` 的关系

票据 `#16` 的实验目标之一是「属性名全量统计：看 `setModal` / `setWindowTitle` / `_build_ui` 到底出不出现」（见交接文档 §5）。**在这个缺陷修好之前，该目标不可能达成**——不是属性名不出现，而是**记录行根本没机会执行**。

**这是「负观测有两个活解释」的又一实例**：属性名记录为空，既可解释为「那些属性名没出现」，也可解释为「配额被耗尽」。两者至今未分离。

## 修法方向（需判断）

- **最小修法**：给属性名记录用**独立的计数器**（如 `logged_attr`）与独立的配额
- **或**：把 `DW HIT` 行的打印改为**不打**或只打前 N 条（它是调试噪音，对结论无用）
- **并修汇总措辞**：把 `已记录 %d 条` 的语义改清楚——它当前计的是 DW HIT 行数，与前面的「匹配目标属性名的命中」不同源

## 验收

- [ ] `hwbp_ctrl.py` 重跑后，**属性名记录行数 > 0**（若仍为 0，须证明是「确无匹配属性名」而非「配额被耗尽」）
- [ ] `DW HIT` 行与属性名记录行**各有独立配额**，互不挤占
- [ ] 汇总段的计数语义明确——不再用计 `DW HIT` 的变量去描述属性名记录数
- [ ] 修复前后各跑一次，`DW HIT` 的命中总量量级不变（40 万级）
- [ ] `setModal` / `setWindowTitle` / `_build_ui` **到底出不出现**有明确答案（这是 `#16` 的原问题）
