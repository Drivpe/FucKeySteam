# 03 — 迁移 `L()`：35 个脚本改用库函数

**What to build:**

35 个脚本里的 `L()` 定义删掉，改为从 `probe_lib` 取用。每个脚本保留的只是「日志写到哪个文件」——函数本身不再各写一份。

**为什么这批放在最前：** `L()` 的爆炸半径最大（35 个脚本），但**风险最低**——实测 35 份实现的功能完全等价，输出字节相同，差异只在缩进风格与句柄变量名（`f` / `out_log`）。收益与风险的比值最好，且它是验证「收口方式可行」的第一个真实样本。

**范围外的两类：**

`lf_test.py` 与 `stage.py` **不纳入**。它们的 `L()` 带时间戳前缀（`[14:23:01] xxx`），而这种需求来自脚本类型——这两个不含 `WaitForDebugEvent`，是静态分析/诊断脚本，跑得极快、输出极少，需要墙钟时刻区分多次运行。时间戳不是风格差异，是它们的真实需求。本票不碰它们。

**验收方式：** 每个脚本迁移后运行一次，日志与迁移前**逐行一致**。`_re/backup/` 下有 9 个轮次备份含历史日志可供对拍。不要只跑一个代表性脚本——35 份全过，这是本票的验收标准，不是抽样。

**运行环境**：跑样本需 Windows + 提权。提权触发机制见 `../ELEVATION-HOWTO.md`（一次性注册，之后非提权会话可用 `Start-ScheduledTask` 触发）。执行器带提权闸，非提权时会拒绝运行——**不要绕过**，非提权下样本会在约 2 秒后崩于 `0xc0000005`，日志会误导。

- [ ] 全部 35 个脚本的日志输出与迁移前逐行一致（含句柄名为 `out_log` 的 4 个 `mydbg` 脚本）
- [ ] `lf_test.py` 与 `stage.py` **未被修改**（`git status` 中无这两个文件）

- [ ] `_re/ghidra/README.md` 中的脚本清单未因本票失效（若清单记录了函数结构，同步更新）
