# 02 — probe_lib 补入四个业务函数（保留全部旧实现）

**What to build:**

把四个业务函数补进 `probe_lib.py`：写日志的 `L()`、读目标进程内存的 `rpm()`、从内存解出 Python 字符串的 `read_pystr()`、给线程设硬件断点的 `set_hwbp()`。

**这一票不改任何脚本。** 目标是让库具备这些能力，同时所有旧实现原地保留——库加了新本事，但还没人用它。

库的形状遵循既有约定：`probe_lib.py` 的文档字符串里已经立下「统一在此定义一次，脚本不得再抄」的规矩（见 `enable_debug_priv` / `current_process_handle` 的说明），本次是继续执行这条规矩，不是新立一套。

**两处必须参数化（因为现存实现有真实分歧）：**

`set_hwbp()` 的断点类型（执行 / 写）与长度必须是显式参数。三个现存实现里，`hwbp16b` 与 `hwbp_ctrl` 设执行断点，`hwbp_data` 设写断点加 4 字节长度——这是**语义分歧**，不是风格差异，不能在库层面选一个。

`read_pystr()` 的偏移尝试策略与是否过滤不可打印字符必须是显式参数。两版现存实现的行为不同（差异已被独立执行证实：同一段含脏字节的内存，一版返回 `b'cleanName'`，另一版返回 `b'set\x01ModacleanName'`，把相邻结构的字节串接进了返回值）。本票**只做参数化表达**，不做统一——统一是第 06 票的事。

`L()` 与 `rpm()` **不需要参数化**。`L()` 的 35 份现存实现输出字节完全相同（差异仅缩进与句柄变量名）；`rpm()` 的 7 份实测功能等价（同样的 `create_string_buffer`、同样的 `ReadProcessMemory`、同样的 `raw[:n]` 返回，只有变量命名与换行不同）。

**Dr7 编码的两个结构缺陷必须原样保留**：无条件抹掉全部 4 个槽导致槽 1–3 静默丢失；从未处理 GD 位（bit13）。库函数需以显式参数**表达**这些行为并让默认值匹配现存实现。修正它们是另一张票，本票不得顺手修。见 `docs/adr/0002`。

**分层要求：** 纯计算（偏移解析、字符过滤、Dr7 位构造）与系统调用（读写内存、读写线程上下文）必须分层，使纯计算部分能在非 Windows 环境验证。库函数接受依赖而非自行创建依赖。

- [ ] `set_hwbp()` 的断点类型与长度是显式参数，默认值为执行断点
- [ ] `read_pystr()` 的偏移策略与过滤开关是显式参数，默认值匹配现存「有回退+有过滤」那版
