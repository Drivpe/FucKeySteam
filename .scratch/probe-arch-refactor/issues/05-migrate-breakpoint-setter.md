# 05 — 迁移 `set_hwbp()`：3 个脚本改用库函数（断点类型显式化）

**What to build:**

3 个脚本里的 `set_hwbp()` 定义删掉，改为从 `probe_lib` 取用，并把**断点类型作为显式参数**传进去。

**这一批的意义不只是搬位置**——它让一个一直隐式的意图第一次在代码里可见：

`hwbp16b` 与 `hwbp_ctrl` 传**执行断点**；`hwbp_data` 传**写断点 + 4 字节长度**。迁移后，`hwbp_data.py` 的调用点会明确写着「我要设写断点」，而不是像现在这样埋在一堆位运算里。

**同时必须修正 `hwbp_ctrl.py` 的三处错误注释。** 该文件的文档字符串（一处）与行内注释（两处）共三处声称自己在设「硬件写断点（RW=01, LEN=11 / RW0=bit16 =01=写）」，但代码只做 `dr7 |= 0x1`——**实际设的是执行断点**。

这个矛盾已经造成过一次实际损失：读结果时把执行断点的数据当成了写断点的数据。

**修正的是注释，不是行为**——`hwbp_ctrl.py` 的断点类型保持执行断点不变（迁移后由参数显式表达）。若认为它「本意」是想设写断点，那是另一张票的决策，不在本票。

**同时删除 `hwbp_ctrl.py` 的死代码**：`WATCH_DATA` 在该文件定义后从未被引用，真正传给断点函数的是 `AUX_RVA`。只有 `hwbp_data.py` 使用 `WATCH_DATA[0]`。这个定义是半成品移植的残留。

**本票不修 `Dr7` 的两个结构缺陷**（槽 1–3 静默丢失、GD 位未处理）。库函数只按参数表达它们。见 `docs/adr/0002`。

- [ ] 3 个脚本的 `set_hwbp()` 定义已删除，改为从 `probe_lib` 取用
- [ ] `hwbp16b.py` 与 `hwbp_ctrl.py` 的调用点显式传执行断点
- [ ] `hwbp_data.py` 的调用点显式传写断点 + 4 字节长度
- [ ] `hwbp_ctrl.py` 的三处错误注释（称写断点）已改为执行断点
- [ ] `hwbp_ctrl.py` 中从未被引用的 `WATCH_DATA` 已删除
- [ ] 新日志的 `Dr7` 值与迁移前逐位相同（本票不改断点语义，只改表达方式）
- [ ] `hwbp16.py` **未被修改**（其 `set_hwbp` 是复数签名，另开票）

> **⚠ 清单陷阱**：`grep -ln 'def set_hwbp' *.py` 会命中 **5** 个文件，其中包含 `probe_lib.py`（**库自身的实现**，不得改）与 `hwbp16.py`（**明确排除**，复数签名、异族）。本票的准确目标是 **3 个脚本**：`hwbp16b.py` / `hwbp_ctrl.py` / `hwbp_data.py`。

**运行环境**：跑样本需 Windows + 提权，机制见 `../ELEVATION-HOWTO.md`。执行器带提权闸，非提权时会拒绝——**不要绕过**。
