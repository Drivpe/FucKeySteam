## What to build

**第二次启动：判定缓存命中是否真的成立。**

样本关闭后重新启动一次，观测这次是否还需要联网、是否还会弹出验证码弹窗。这是整条路线的终点判定——ADR 0001 的全部赌注都压在这里。

判据是一个**否定式观测**（没有弹窗），这是本项目最容易误读的一类结论。因此标准写成合取式，且带一个观测有效性的前提：必须能枚举到主窗口，才能说「没有模态窗口」；否则「没采到」会被当成「不存在」。这是 drift 表里已登记多次的错误模式。

同时要观测 `config/stplug-in/` 与主号目录 `userdata\<main-id>` 是否被改动。后者是既有结论「样本不写主号」的实测复核；前者是样本破坏性行为的信号。

## Acceptance criteria

- [ ] 观测有效性的前提成立：窗口枚举能列出样本的主窗口（证明观测手段确实在工作）
- [ ] 主窗口 `Enabled=True`
- [ ] 不存在同进程的模态窗口，且未观测到 `VerificationDialog`
- [ ] 未观测到可归因到样本进程的、指向 `key.steamofl.com` 的验证用连接
- [ ] 未观测到 `TamperWarningDialog`（「倒卖可耻」）
- [ ] `config/stplug-in/` 下的 `.lua` / `.ks` 未被删除或改写（与备份逐一核对）
- [ ] 主号目录 `userdata\<main-id>` 未被写入
- [ ] 两次启动之间的时间间隔已记录（用于给 `expires_at` 的实际时长积累第一个数据点）
- [ ] 判定结论已明写：命中 / 未命中 / 证据不足，三者择一，不得写成含义模糊的「似乎没问题」
- [ ] 本次运行的完整时间线与原始日志已存档
