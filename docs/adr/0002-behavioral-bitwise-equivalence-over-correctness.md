# ADR 0002：探针脚本重构采用「行为逐位等价优先于正确性」

- **状态**：已接受
- **日期**：2026-09-17
- **决策轮次**：架构重构方案轮（`_re/ghidra/` 首个架构决策）

## 背景

`KeySteam v2.99/_re/ghidra/` 的 84 个探针脚本无 git 历史、零测试，其中一个可提取的重复是
**调试寄存器 Dr7 的断点编码**：族 A 的三份实现（`hwbp16b.py`、`hwbp_ctrl.py`、`hwbp_data.py`）
各自写一遍位运算，其中 `hwbp_ctrl.py ↔ hwbp_data.py` 的代码相似度 J=0.869，是确证的复制体对。

抽取纯函数时暴露出两个**共有的结构缺陷**：

1. **槽 1–3 静默丢失**：三份都无条件写 `dr7 &= ~0xFFFFFFFF`，一次清空全部 4 个断点槽的
   启用位与 RW/LEN，但只重填槽 0。若先设断点 A 再设断点 B，A 的配置被静默清掉。
2. **GD 位（bit13）从未处理**：`hwbp_data.py` 是目录内唯一真正设数据断点的实现，
   而数据断点场景下 GD=0 会使 DR7 写入不生效。该脚本的历史日志可能是在**断点未生效**
   的前提下产生的。

   > **精化（2026-09-17，实测）**：这不是一个**独立**缺陷，而是被**缺陷 1 的掩码顺带抹掉**
   > 的——两者成因是同一个。`0x2000`（GD）落在 `0xFFFFFFFF` 掩码内，故
   > `prev_dr7 & ~0xFFFFFFFF` 无论入参如何都把 GD 清成 0。
   > **不再作为独立缺陷计数**，而是缺陷 1 的一个后果。详见下方修订节。

## 决策

**新函数 `make_hw_bp` 的默认行为必须逐位等价于族 A 的现存实现，包括保留上述两个缺陷。**

以显式参数 `clear_all_slots=True` 表达缺陷 1 的语义（默认值即等价路径）；缺陷本身**另开票据**处理。

**不采用**"顺手修掉"的做法。

## 理由

- **可机械判定的安全网优先**：逐位等价使"新函数输出 == 旧实现输出"成为可自动验证的断言。
  在一个零测试、无版本控制的目录里，这个安全网的价值高于单个 bug 的修复。
- **修缺陷会破坏可比性**：若新函数修正了 DR7 语义，新旧脚本产出的日志**不可直接比较**，
  而该目录的历史日志正是当前逆向结论的证据基础。
- **缺陷有独立的影响面**：缺陷 2 可能影响既有实验结论（不只是代码整洁），
  必须单独查证，不能顺手夹带在重构里。

## 后果

**负面（须明示）**：`make_hw_bp` 的默认路径**携带一个已知 bug**。未来读者看到
`clear_all_slots=True` 会认为这是疏漏，从而"好心修好"它——**那样会静默改变所有探针的行为，
并使等价断言失效**。本 ADR 的首要目的就是阻止这种"修复"。

**正面**：重构与缺陷修复解耦。重构可立即在 Linux 侧验证（纯整数运算，不碰 Windows、不碰样本），
缺陷的影响面调查独立推进。

**未决**：
1. 缺陷 2（GD 位）是否真的让 `hwbp_data.py` 的断点未生效——需证据，不能照搬手册。
   若成立，该脚本的历史日志及其下游结论（含 `docs/suppressing-the-dialog*.md`、
   票据 `#16`–`#18`）需重新审视。
2. 缺陷 1 的修正路径何时开启，取决于何时不再需要与历史日志对比。
3. `hwbp16.py` 被实测判定为**异族**（J=0.27，函数签名 `addrs` 复数 vs 另三份 `addr` 单数，
   两者调用约定不兼容），不在本决策的等价断言范围内，另行开票。

## 修订 2026-09-17（第二处，缺陷 2 的前提被推翻）

**原表述（已被推翻，保留原文仅为记录思路）**：缺陷 2 是「GD 位（bit13）从未处理，而数据断点场景下 GD=0 会使 DR7 写入不生效」，据此推断 `hwbp_data.py` 的历史日志**可能是在断点未生效的前提下产生的**。

**实测结论（2026-09-17，见 `.scratch/probe-arch-refactor/findings-dr7-gd.md`）：这条因果链在本代码里造不出来。**

`hwbp_data.py` 写 `Dr7` 前执行 `dr7 = ctx.Dr7 & ~0xFFFFFFFF`。该掩码覆盖 **bit0–31**，而 GD 在 **bit13** —— 所以 GD 在读入后被清成 0 才回写。终值恒为 `0xd0001`，**与入参无关**；入参带不带 GD，输出逐位相同（12 组入参 × 3 份实现的独立对拍，零不一致）。

**因此 GD 位是「结构性空假设」，不是「设错了值」**。「GD=0 使写入不生效」既不成立、也无法被这段代码触发。

**同时证伪的还有原推断的下游**：`hwbp_data.py` 的历史日志中**没有命中数需要解释**——两份日志（`hwbpData_d1.txt` 327 字节、`hwbpData_wa.txt` 313 字节）的汇总段均写明 `命中总数: 0`。该脚本**从未产出过任何命中**。

**影响面：既有结论全部不受波及。** `docs/suppressing-the-dialog.md`、`docs/suppressing-the-dialog-evidence.md`、`docs/probe-index.md` 三份**零处引用 hwbp**（证据底座是静态常量分析与页保护断点）。票据 `#16`–`#18` 的实际结论来自 `hwbp16b` / `hwbp_ctrl`，**皆非 `hwbp_data`**。

**本 ADR 的决策不变**：保留缺陷、逐位等价优先。被推翻的只是质疑该缺陷的**动机**（「可能影响既有结论」不再成立），不是缺陷的存在（`& ~0xFFFFFFFF` 清空槽 1–3 仍是真缺陷）。判据未被动摇。

### 本次暴露的一个**新**缺口（未被原 ADR 预见）

`hwbp_data.py` 的 0 命中**不代表机制正常**——它有**三条未分离的活解释**：

1. 目标地址在观测窗口内确实未被写入；
2. 那是「读」操作，而写断点本就不捕获读；
3. **写断点的编码根本没设上。**

**第 3 条不可排除**，且有加重证据：**整个目录不存在写断点的正对照**——`hwbp_data.py` 是唯一设数据断点的脚本，而它从未命中过一次。

加重证据（本次核实）：**三个 hwbp 脚本都不记录「设断点成功/失败」**。`hwbp_ctrl.py` / `hwbp16b.py` 靠大量命中**反证**了机制有效；`hwbp_data.py` 因 0 命中，**没有任何反证**。

另有一处**结构性风险**（本次核实）：`hwbp_data.py` 的断点设在 `code in (3, 2)`（CREATE_PROCESS / CREATE_THREAD）且要求 `if main_base:`，而 `main_base` 只在 LOAD_DLL 事件里赋值。主线程的创建事件先于 DLL 加载，故该脚本只对**加载后新创建**的线程设断点。

**处置**：另开一张票（工单 08），用两个最小实验分离上述三条解释。**在此之前，不得把 `hwbp_data.py` 的 0 命中当作任何结论的证据。**

**同日另一处发现（与本 ADR 无关但须记）**：`hwbpData_d1.txt` 与 `hwbpData_wa.txt` **出自两代 `hwbp_data.py`**（汇总段标题不同：`-- 属性名 x 调用者 频次 --` vs `-- 写入者频次 --`，后者匹配当前文件）。二者均 0 命中，不影响本结论，但**后续任何新旧日志对拍不得当成同一代**——这正是本 ADR 修订节警告过的那类陷阱。

## 修订 2026-09-17（同日，范围扩大后）

**背景变化**：本 ADR 原定范围是「把 `Dr7` 编码收成一个纯函数」（服务族 A 三份）。经 seam 确认后，操作者将范围扩大为「把四个业务函数补进 `probe_lib.py`」，服务 **35 个脚本**。

**范围扩大后暴露出两处无法用「逐位等价」处理的冲突**，本 ADR 的默认立场在此**被有意偏离**：

| 冲突 | 具体 | 本次处置 |
| --- | --- | --- |
| `read_pystr()` 两版行为不同 | 一版有偏移回退 + 可打印过滤；另一版只读固定偏移、无过滤。同一脏内存下返回 `b'cleanName'` vs `b'set\x01ModacleanName'`（跨结构串接） | **统一为「有回退 + 有过滤」那版**，即**接受行为变更** |
| `set_hwbp()` 三版语义不同 | `hwbp16b`/`hwbp_ctrl` 设执行断点；`hwbp_data` 设写断点（4 字节） | **断点类型显式参数化**，三方语义都保留，但意图第一次在代码中可见 |

**为何此处偏离逐位等价**：两版 `read_pystr` 中存在**明确更正确的一版**——直读版会把相邻结构的字节串接进返回值，这是缺陷而非设计。操作者在知晓代价（`hwbp_ctrl` / `hwbp_data` 的字符串命中统计会变）的前提下选择统一。

**本 ADR 的原始立场仍然有效**，且适用范围未变：

- `Dr7` 编码的**结构缺陷（槽 1–3 静默丢失）仍然保留**，库函数以显式参数（`clear_all_slots`）表达，默认值匹配现存行为。属缺陷票。
  GD 位问题已查明为同一成因的后果（见修订节），不是第二个独立缺陷。
- `L()` 的 35 份**功能等价**，统一为零风险，不涉等价性取舍。
- `rpm()` 三份**逐字同一**，无取舍。

**阅读指引**：本 ADR 的正文立场（保留缺陷）与本次修订（统一 `read_pystr`）**并存不矛盾**——判据是「被取舍的两版中是否存在明确更正确的一版」。有，则统一；无（如 `Dr7` 缺陷的两侧是「保留现状」与「修正现状」，而现状本身是缺陷），则保留。未来的类似判断应沿用这条判据。

**未决**：`read_pystr` 统一后，`hwbp_ctrl.py` / `hwbp_data.py` 的历史日志与新日志**不再逐行可比**（命中统计会变）。需在这两个脚本的迁移记录中标注，避免后人误以为是迁移引入了 bug。
