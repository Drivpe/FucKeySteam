## 5. ★ 本轮新发现：主窗口随机时刻最小化（已归因，与补丁无关）

### 5.1 现象

r42 在 4 次运行中的最小化首现时刻：`未出现 / 63.3s / 128.9s / 255.3s`。**时间随机分布**，且最小化后持续保持到实验结束（非瞬时抖动）。

### 5.2 归因证据（四路收敛）

**证据 1 —— 系统级事件钩子（决定性）**

`SetWinEventHook(WINEVENT_OUTOFCONTEXT)` 监听 `EVENT_SYSTEM_MINIMIZESTART/END`：

| 实验 | 时长 | 捕获系统事件 | **目标进程自身 MINIMIZESTART** |
|---|---|---|---|
| hook1 | 300s | 456 | **0** |
| hook2 | 420s | 2121 | **0** |

**目标进程从未发起最小化。** 钩子确认生效（成功捕获目标进程自身的 `OBJECT_SHOW` + `SYSTEM_FOREGROUND`）。

**证据 2 —— 那 2 次 MINIMIZEEND 的归属**

```
t=115.83  MINIMIZEEND  own=False  img=firefox.exe   cls=MozillaWindowClass
t=127.44  MINIMIZEEND  own=False  img=Weixin.exe    cls=Qt51514QWindowIcon
```
全属**其他程序**。

**证据 3 —— 前台权抢占日志（hook2，13 次 FOREGROUND 事件）**

```
t=1.23    own=True   KeySteam_r42.exe   ← 仅启动时获得前台
t=115.73  own=False  explorer.exe  (Shell_TrayWnd)
t=127.34  own=False  explorer.exe
t=127.44  own=False  Weixin.exe
t=131.06  own=False  OpenWith.exe
t=132.71  own=False  WINWORD.EXE   ← 用户正在编辑文档
```
宿主机有**真实用户活动**（Firefox / 微信 / Word / 资源管理器），系统前台权被反复抢占。

**证据 4 —— 静态排除进程内部路径**

```
main.dll 内 "user32.dll" 导入        : 0 处
main.dll 内 "ShowWindow" 字符串       : 2 处，均为结构体字段名
                                       (wShowWindow / awShowWindow = STARTUPINFO 参数)
main.dll 内 "SetWindowPlacement"     : 0 处
main.dll 内 "SW_MINIMIZE"            : 0 处
```
⇒ 无直接 Win32 窗口操作路径，窗口全部经 Qt 运行时。

**证据 5 —— 只读追踪 240s**

前台窗口 `firefox.exe` **130/130 帧**恒占；光标固定不动 `(1061,868)`；目标窗口 `iconic=True` 仅出现在启动瞬间 `t=0.36s`（尚未显示），全程零最小化。

### 5.3 结论

**最小化是宿主环境交互（用户操作前台程序 / 窗口管理器注意力转移）的产物，不是补丁行为，也不是程序逻辑缺陷。** 判据层面应对方式：把 `MAIN_MINIMIZED` 与 `MODAL_DIALOG` 分开统计——前者不算失败。

**方法学教训（本轮踩坑）**：
1. `<script>.py` 脚本内嵌 `cp` 同名文件会以 exit 1 中断整个命令链（`bash-63` 事故），批处理脚本勿混入幂等 `cp`。
2. 验收器不得用**尺寸阈值**过滤窗口——最小化窗口会被误判为不存在。必须用 `IsIconic` / `WS_MINIMIZE`。
3. `E9` 是 5 字节指令；用 6 字节算 rel32 落点会差 1 字节，恰好在 GA 处产生假阴性。
4. 槽地址落在 `.data` 的 BSS 未初始化区时静态读不到（运行期才填充），须改搜**字符串本体**。
5. WinEventHook 判定「某行为是否由进程自身发起」是可靠手段：`own` 标志 + `idEventThread` 可直接区分内外来源。
