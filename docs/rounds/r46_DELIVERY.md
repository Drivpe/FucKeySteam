# r46 交付报告 —— 「用户菜单尚未初始化」根因定性与修复

**日期**：2026-09-28
**用户关键反馈**：**r40 界面正常；r41 及其后所有版本都弹出 `[ 警告 ] 用户菜单尚未初始化`**
**结论**：根因是 **r42 报告 §6.4 的一处错误判断** —— 它断言 r40 的 `0xF75F98` 补丁「无需」，实测证明**该补丁是初始化放行的必要条件**。已交付 `KeySteam_r46_可用.exe`，实测数值与 r40 逐位一致。

## 1. 用户反馈是本轮的决定性证据

上一轮（r44）我未能复现用户所报症状，误判为「日志面板无害记录」。用户明确指出 **r40 正常、r41 起异常**，这把问题从「文本残留」彻底转向「**r40→r41 之间的行为回归**」。

据此对比 r40 与 r41 的补丁集：

| 版本 | 补丁点 | 差异字节 |
|---|---|---|
| **r40** | `0xF75F98` `74→EB`、P1 `0xF93770`、`0xFE7990` `74→EB` | 8 |
| r41 | **G1** `0xF7659F`、P1、`0xFE7990` `90 90` | 12 |
| r42 | **G1**、P1、**GA** `0xFE7967` | 14 |

**r41 用 G1 替换掉了 r40 的 `0xF75F98`** —— 这就是回归点。

## 2. 根因机制（已实证）

### 2.1 `0xF75F98` 的语义

位于 `_apply_integrity_result`（函数区间 `0x180F769B0..0x180F7701A`）：

```asm
0x180f76b96  test  eax, eax
0x180f76b98  je    0x180f76c0d     ★ 原：校验失败 → 走封锁分支
                                     r40 改 74→EB 后：jmp 0x180f76c0d
0x180f76b9a  ...（完整性失败处理：装 TAMPERED 状态、封锁 UI）
0x180f76c0d  mov   rdi, [rip+0x4c6f24]      ← 正常继续路径
0x180f76c1c  jmp   0x180f76fd0
0x180f76fd0  ...                             ← 清理 + 尾声
0x180f77019  ret
```

`74→EB` 使**完整性校验失败分支被无条件跳过**，函数从正常路径返回。

### 2.2 缺失它的后果

r41/r42 用 G1 只压住了 `show_tamper_warning` 的**告警弹窗**，但 `_apply_integrity_result` 仍返回 TAMPERED 状态。`_continue_initialization` 因此不再下发 `users_menu_update` / `games_list_update`：

- 用户菜单为空 → 后续动作取不到菜单 → **`[ 警告 ] 用户菜单尚未初始化`**
- 游戏列表为空 → 需手动导入

**r40 之所以"看起来正常"，不是因为它的 P2 补丁对，而是因为 `0xF75F98` 让初始化走完了。**

## 5. 撤销的中间结论（本轮自我纠正）

1. **r42 §6.4「`_apply_integrity_result` 的 `0xF76B98` 未使用，无需该点」→ 错误。** 该点 RVA 为 `0xF76B98`（FO `0xF75F98`），是初始化能否走完的开关。
2. **r44 报告中「`[ 警告 ]` 提示无害、程序照常可用」→ 错误。** 它标志**启动初始化被截断**，用户菜单与游戏列表均未填充，属功能性缺陷。
3. **r42 §4「r40 的 P2 补丁 `0xFE7990` 反效果」→ 需重新审视。** r40 同时具备 FIX + P2，实测初始化完整且无过期报警；说明在 FIX 存在的前提下，P2 并未产生 r42 所描述的危害。该点语义应按「与 FIX 联合作用」重新评估，不宜单独定性。
4. **r43「窗口枚举判据 + 唯一引用点」→ 方法论不完整。** 它无法发现**功能退化**：r42 弹窗帧确实为 0，但界面是空壳。**验收必须加入「初始化完整性」指标**，不能只看「有没有弹窗」。

## 6. 方法论增量（本轮）

1. **「有没有弹窗」不足以判定成功**。必须同时验证**功能完整性**：日志面板是否填充、列表是否加载、关键状态字符串是否出现。r43 的四路验证全部漏掉这一点。
2. **像素定量是可靠的功能判据**。裁剪固定区域统计亮像素数，可给出**数值化**的 A/B 结论（11870 vs 1673），并设顶栏为对照基准排除恒真/恒假。
3. **用户的「哪个版本正常」是最强定位信息**。一句「r40 正常」直接锁定回归区间为 r40→r41，使补丁集差异对比一步到位——远胜于盲目复现。
4. **历史报告的「无需该点」结论必须实测复核**。优化掉一个"冗余"补丁，可能正是把功能打断的那一步。
